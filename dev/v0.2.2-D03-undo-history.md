# D03 Undo の完全化

状態: 短期 **0.2.2**。v0.1 で一部だけ実装した Undo を完成させる。

## 背景

`HistoryState` は直近 50 回の `Vec<MoveAction>` を積む。`MoveAction` は `hwnd`, `old_rect`, `new_rect`。rotate/swap/escape/gather は push 時点で `new_rect = old_rect` のまま。Undo は `SetWindowPos` で `old_rect` に戻すだけ。

そのため:

- 最大化ウィンドウは移動時に restore → move → maximize されるが、Undo は通常ウィンドウのまま old 座標に置かれる。
- フルスクリーン RDP は専用シーケンスで動くが、Undo は枠座標に戻そうとして壊れる。
- 整列（arrange）だけは `new_rect` を正しく入れている。
- Z 順は Undo 時に全部 HWND_TOP へ逆順適用しており、他アプリとの重なりが変わる。

## 目的

「直前の本ツール操作」を、位置・サイズ・最大化/最小化/通常/フルスクリーンの別まで戻す。ピンと除外で動かさなかった窓は履歴に載せない（現状どおり）。

Redo は入れない（SCOPE 外。ホットキーも無い）。

## 機能概要

- `MoveAction` に移動前の表示状態を保存する。
- 移動実行後に実際の `new_rect` と状態を書く（予測値ではなく、可能なら移動後の `GetWindowRect`）。
- `handle_undo` は状態に応じて ShowWindow / RDP 再シーケンス / SetWindowPos を選ぶ。
- 無効 HWND はスキップして残りを戻す。

## ユースケース

- UC-1 最大化されたブラウザをシフトしたあと Undo → 元モニタで最大化のまま。
- UC-2 整列したあと Undo → 整列前の矩形へ。
- UC-3 全画面 mstsc を動かしたあと Undo → 元モニタで全画面に戻る（D03 の最難関。失敗時はログして通常 Undo に落とさない）。
- UC-4 対象プロセスが終了していたらその窓だけスキップ。

## 画面遷移

なし。失敗しても OSD は出さない（PLAN_REJECT）。ログに `Undo skipped hwnd=` を info で残す。

## 処理フロー

```
操作開始
  windows = filter(pin, rules)
  snapshot = windows.map(capture_state)
  実行 move / arrange
  for each: snapshot[i].new = capture_state(hwnd)  // 失敗時は計算上の目標矩形
  history.push(snapshot)

Undo
  pop
  for action in reverse(z-order 保存順)
    if !IsWindow: continue
    restore(action.old)
```

`capture_state` は `WindowInfo` から `is_maximized` / `is_minimized` / `is_fullscreen` / `rect` / `process_name` をコピー。

## データ構造

```rust
#[derive(Debug, Clone)]
pub struct WindowPlacementState {
    pub rect: MonitorRect,
    pub is_maximized: bool,
    pub is_minimized: bool,
    pub is_fullscreen: bool,
    pub process_name: String,
}

#[derive(Debug, Clone)]
pub struct MoveAction {
    pub hwnd: isize,
    pub old: WindowPlacementState,
    pub new: WindowPlacementState,
}
```

serde は不要（メモリのみ）。

## API 設計

Tauri コマンド追加なし。内部関数:

### `capture_placement(win: &WindowInfo) -> WindowPlacementState`

### `restore_placement(hwnd: isize, state: &WindowPlacementState) -> Result<(), RestoreError>`

分岐:

1. `is_fullscreen && process_name == mstsc.exe` → 既存 `move_fullscreen_rdp` 相当を「目的モニタ」へ。目的モニタは `state.rect` の中心が属するモニタ。
2. `is_minimized` → `ShowWindow(SW_MINIMIZE)`（座標は placement に任せる）
3. `is_maximized` → restore → SetWindowPos(rect) → SW_MAXIMIZE
4. それ以外 → SetWindowPos(rect)

`move_fullscreen_rdp` は今 dest_monitor を取る。Undo から呼ぶために `pub(crate)` 化する。

## テスト方針

純粋部分: `WindowPlacementState` の構築、最大化 Undo の「呼ぶべき Win32 順」をテストするために、restore をトレイトにしないと HWND が要る。

0.2.2 での現実的な線:

- `restore_plan(state) -> RestorePlan` を純粋関数にする。
- RestorePlan は enum: `Position`, `Maximize { rect }`, `Minimize`, `RdpFullscreen { dest_hint_rect }`。
- この enum を単体テストする。実際の SetWindowPos は手動。

```rust
pub fn restore_plan(state: &WindowPlacementState) -> RestorePlan { ... }
```

入力例: `{ rect: (0,0,1920,1080), is_maximized: true, ... }`  
出力例: `RestorePlan::Maximize { rect: ... }`

境界: 全部 false → Position。fullscreen かつ mstsc → RdpFullscreen。fullscreen かつ game.exe → Position（ゲームは再全画面シーケンスを持たない。旧 rect がモニタ全体なら SetWindowPos で足りることが多い）。
