# D04 切断モニタのウィンドウ回収

状態: 短期 **0.2.2**。SPECv0.1 の未完了項目。

## 背景

SPEC 3-4: ディスプレイ切断時、その画面に残ったウィンドウをプライマリへ回収する。

実装: `hotplug.rs` が隠しウィンドウで `WM_DISPLAYCHANGE` を受け、`display-changed` をフロントへ emit する。`App.tsx` はモニターマップを再読込するだけ。回収ロジックは無い。

切断後は、Windows が窓を別のモニタへ移すこともあれば、窓が仮想空間の古い座標に残ることもある。本ツールのグループ設定も古い `\\.\DISPLAYn` 名に紐づいたままになり得る。

## 目的

構成変化のたびに:

1. 設定 UI のマップを更新する（既存）。
2. どの現役モニタにも載っていない可視ウィンドウを、設定上のプライマリ（無ければ OS プライマリ）へ移動する。
3. 履歴に1エントリとして積み、Undo できるようにする。

OS が既に回収済みなら、交差判定で「どこかのモニタに載っている」となり no-op。

## 機能概要

- `hotplug` のコールバックで Rust 側回収を実行する（フロント依存にしない。設定画面が閉じていると今は UI しか更新されないが、回収は常駐中に必要）。
- デバウンス 500ms。接続のたびに DISPLAYCHANGE が複数飛ぶ。
- 除外ルールとピンは尊重する（ゲーム全画面をプライマリへ引っ張らない）。
- 最小化窓は既定除外ルールで除外される。回収対象外でよい。

## ユースケース

- UC-1 ノートに外付けを足して作業し、抜く。外付け上の窓がノート画面へ来る。
- UC-2 設定画面を開いていないトレイ常駐だけでも回収される。
- UC-3 ピンした時計ウィジェットは動かない。
- UC-4 同じ DISPLAYCHANGE が3連続 → 回収は1回。

## 画面遷移

マップが開いていれば既存の `display-changed` で再描画。追加 UI なし。

## 処理フロー

```
WM_DISPLAYCHANGE
  reset debounce timer 500ms
  on fire:
    monitors = get_all_monitors()
    if monitors.is_empty(): return
    dest = primary from config else OS primary
    windows = get_target_windows() filtered by pin+rules
    orphans = windows where group_windows_by_monitor の所属面積が 0
      （logic の現実装は面積0だと index 0 に入る。ここがバグ源）
    if orphans.is_empty(): emit display-changed; return
    move_windows(orphans, synthetic_src, dest)
    history.push
    emit display-changed
```

**重要**: `group_windows_by_monitor` はどのモニタとも交差しない窓を `matched_idx = 0` に入れる。回収判定には使えない。

新規: `fn owning_monitor_index(win, monitors) -> Option<usize>`  
交差面積最大。ゼロなら None。

## データ構造

追加設定フィールドは任意。0.2.2 では設定を増やさず常に回収 ON。OFF が欲しくなったら中期で `recover_on_unplug: bool`（default true）。

## API 設計

Tauri コマンドなし。

### `pub fn owning_monitor_index(win: &WindowInfo, monitors: &[MonitorInfo]) -> Option<usize>`

入力: 窓が (4000,0)-(5000,1000)、モニタが 0..1920 と 1920..3840 のみ  
出力: `None`

入力: 窓が (2000,0)-(2500,500)  
出力: `Some(1)`

### `pub fn handle_display_change(app: &AppHandle)`

hotplug の emit 前に呼ぶ。

デバウンス実装: `OnceLock<Mutex<Option<JoinHandle>>>` で前回スレッドを殺さず、世代番号 `AtomicU64` を増やし、sleep 後に世代が同じときだけ実行。

## エラーハンドリング

| 状況 | 動作 |
| --- | --- |
| モニタ0枚（ヘッドレス） | 回収しない |
| dest 特定不能 | no-op |
| 移動失敗 | 個別に log、他は継続 |
| デバウンス中にアプリ終了 | ベストエフォート |

## テスト方針

`owning_monitor_index` と orphan 抽出を単体テスト。

正常: 2モニタ、窓は両方に載っている → orphan 0。  
異常: モニタ1枚、窓の座標が 10000,0 → orphan。  
境界: 枠1pxだけ交差 → Some。面積0（接するだけ）→ None。  
パフォーマンス: 窓200 + モニタ8 をフィクスチャで 10ms 以内。  
セキュリティ: 対象外（ローカル）。

DISPLAYCHANGE そのものは手動（実機でケーブル抜く）。

### サンプル

```rust
pub fn owning_monitor_index(win: &WindowInfo, monitors: &[MonitorInfo]) -> Option<usize> {
    let mut best: Option<(usize, i32)> = None;
    for (i, m) in monitors.iter().enumerate() {
        let l = win.rect.left.max(m.monitor_area.left);
        let r = win.rect.right.min(m.monitor_area.right);
        let t = win.rect.top.max(m.monitor_area.top);
        let b = win.rect.bottom.min(m.monitor_area.bottom);
        if r > l && b > t {
            let area = (r - l) * (b - t);
            if best.map(|(_, a)| area > a).unwrap_or(true) {
                best = Some((i, area));
            }
        }
    }
    best.map(|(i, _)| i)
}
```
