## Q1. 対象ユーザーと製品の核（最優先）

現状の核は「3〜6台のマルチモニタで、画面上のウィンドウ群を比率・Z順を保ったまま入れ替える」こと（[USERS_GUIDE.md](../docs/USERS_GUIDE.md)）。

- A. 現行のまま。パワーユーザー向け、キーボード優先、Windows 専用の画面入れ替えツール
- B. 一般向けに広げる（初回ウィザード、OSD、単体ウィンドウ移動など）
- C. マルチモニタ作業環境の総合ツールへ拡張する（ディスプレイ配置、解像度、プロファイル）

**推奨**: A。B と C は [PLAN_REJECT.md](PLAN_REJECT.md) および PowerToys / 設定アプリと競合する。

**影響**: A なら短期は信頼性。C なら D08 が次リリース候補になる。

**回答: A**

## Q2. SPECv0.3 の扱い

`dev/history/v0.3.0-req-draft.md` は箇条書きの下書きで、次の2系統が混在している。

1. 任意ウィンドウのサイズ変更ダイアログ（製品に隣接）
2. OS のモニタ座標を手入力・ドラッグで書き換え、シリアルで保存/読込（Windows のディスプレイ設定と同等）

- A. どちらも次リリースに含めない。信頼性リリースを 0.3.0 にする
- B. 1 のみ中期に入れる。2 は採用しない
- C. 1 と 2 の両方を次リリースにする
- D. 2 だけ先行する

**推奨**: A。2 は管理者権限・ドライバ・複製モード・切断済みディスプレイで失敗しやすく、自動テストがほぼ不可能。

**回答: A**（版番号は Q13 により 0.2.2。D07/D08 は現行方針では実装しない）

## Q11. データ保存方式

## Q12. セキュリティ要件

現状: 一般権限既定、管理者は明示的に再起動、`csp: null`、`open_url` は任意 URL を `cmd /C start`、コード署名なし。

確認したい最低ライン:

- コード署名（Authenticode）を次リリースで行うか
- 管理者起動を既定にするか（推奨しない）
- GitHub 更新確認以外の通信を禁止するか
- `open_url` を https の GitHub ドメインに限定するか（推奨する）

**回答:** コード署名は MSI X のためにする予定で、本リポジトリ／作者作業では行わない。その他のセキュリティ要件は変更しない（管理者は既定にしない、CSP と `open_url` 制限は必須化しない）。自動通信の停止は Q5-B で担保する。
