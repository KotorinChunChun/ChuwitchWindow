# D07 アクティブウィンドウの指定サイズ変更

状態: **現行方針では実装しない**（決定 Q1-A / Q2-A）。再検討時は DECISIONS を更新してから着手する。

SPECv0.3 原文: 「任意のウィンドウの解像度を指定サイズに変える機能。ショートカットキーを押したら変更画面が出てくる。」

## 背景

本ツールは「窓をモニタ間で移す」が核で、単体のリサイズは FancyZones / 標準スナップと近い。ただし「この窓を 1920x1080 のクライアントにする」は配信・RDP・キャプチャで実需がある。PLAN_REJECT の「単体移動」とは別（サイズのみ、モニタは変えない）。

## 目的

フォアグラウンドウィンドウを、プリセットまたは数値でリサイズする。位置は現在のモニタ作業領域内にクランプする。除外・ピンはリサイズも拒否（動かさない方針と一致）。

## 機能概要

- ホットキー（案: `Win+Ctrl+Alt+R`。衝突確認必須）で arrange と同様のボーダーレス WebView を前面に出す。
- プリセット: 1280x720, 1920x1080, 2560x1440, 3840x2160, 作業領域最大化（最大化メッセージではなくサイズ指定）。
- 幅・高さの数値入力。Enter で実行、Esc で閉じる。
- リサイズ不可（WS_THICKFRAME なし等）はボタンを disabled にし理由を出す。
- 履歴に載せ Undo 可能（D03 前提）。

## ユースケース

- UC-1 配信ソフトのキャプチャサイズにブラウザを合わせる。
- UC-2 誤って巨大化した窓を 1920x1080 に戻す。
- UC-3 全画面ゲームが前面 → 除外ルールで拒否、ポップアップに「対象外」。

## 画面遷移

```
ホットキー
  → 前面窓をスナップショット（HWND）
  → #resize ハッシュのポップアップ（arrange と同じパターン）
  → プリセット or 適用
  → 閉じる
フォーカス喪失 → 閉じる（arrange と同じ）
```

設定タブは増やさない。ホットキーだけ設定・常駐タブに1行追加。

## 処理フロー

```
show_resize_window
  hwnd = GetForegroundWindow（ポップアップ表示前）
  store LAST_TARGET_HWND
  show webview

exec_resize(width, height)
  win = get info for LAST_TARGET_HWND
  if pin or excluded or !resizable: Err
  dest = clamp to work_area of owning monitor, keep top-left if fits else center
  SetWindowPos
  history.push
  close
```

クライアント領域とウィンドウ領域: 指定は **外側（ウィンドウ矩形）** とする。DPI は物理ピクセル（既存 move と同じ）。文言で「ウィンドウ枠込みのピクセル」と書く。

## データ構造

`AppConfig.resize_hotkey: String` default `"Win+Ctrl+Alt+R"`  
serde default で旧 config 互換。

静的: `LAST_TARGET_HWND: Mutex<Option<isize>>`（arrange の hmonitor と同じパターン）

## API 設計

```rust
#[tauri::command]
fn exec_resize_cmd(width: u32, height: u32) -> Result<(), String>;

#[tauri::command]
fn get_resize_target_cmd() -> Result<ResizeTargetUi, String>;

struct ResizeTargetUi {
    title: String,
    process_name: String,
    current_w: i32,
    current_h: i32,
    max_w: i32, // work area
    max_h: i32,
    can_resize: bool,
    block_reason: Option<String>,
}
```

入力例: `{ width: 1920, height: 1080 }`  
成功: `Ok(())`  
失敗: `Err("window is not resizable")`

幅高さの範囲: 100..=16384。0 や負は TS でも拒否。

## エラーハンドリング

HWND 無効、対象外、小さすぎ、作業領域より大きい → ダイアログではなくポップアップ内テキスト。適用ボタンを押せない。

## テスト方針

`clamp_rect(proposed, work_area) -> MonitorRect` 純粋関数。

正常: 1920x1080 が 2560x1440 作業領域に収まる。左上維持。  
異常: 8000x8000 → 作業領域サイズにクランプ。  
境界: 幅 = 作業領域幅ちょうど。  
セキュリティ: 他プロセスの任意 HWND をフロントから渡さない。必ず LAST_TARGET_HWND。

### サンプル clamp

```rust
pub fn clamp_size(width: i32, height: i32, work: &MonitorRect, current_left: i32, current_top: i32) -> MonitorRect {
    let max_w = (work.right - work.left).max(100);
    let max_h = (work.bottom - work.top).max(100);
    let w = width.clamp(100, max_w);
    let h = height.clamp(100, max_h);
    let mut left = current_left;
    let mut top = current_top;
    if left + w > work.right { left = work.right - w; }
    if top + h > work.bottom { top = work.bottom - h; }
    if left < work.left { left = work.left; }
    if top < work.top { top = work.top; }
    MonitorRect { left, top, right: left + w, bottom: top + h }
}
```
