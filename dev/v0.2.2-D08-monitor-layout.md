# D08 OS モニタ配置の編集とプロファイル

状態: **現行方針では実装しない**（決定 Q1-A / Q2-A）。製品の方向性が変わる機能のため、再検討時は DECISIONS を更新してから着手する。

SPECv0.3: 選択モニタの左上 XY 表示と手入力、ドラッグで配置変更、OS 側変更のリロード、シリアルでセーブ/ロード。

## 背景

これは Windows の「ディスプレイの配置」と同じ層（`ChangeDisplaySettingsExW` / CCD API）である。失敗するとデスクトップが消え、複製モードや無効出力で復旧が難しい。本ツールの核（HWND 移動）より権限・ドライバ・テスト不能領域が重い。

現状 `serial_number` は EDID ではなく PnP DeviceID 部分文字列。抜き差しで変わりうる。プロファイルのキーにしてはいけない。

既存 `display-changed` はマップ再読込済み。SPECv0.3 の「OS が変えたらリロード」は D08 全体を承認しなくても、短期の D04 で足りる。

## 目的（承認された場合）

設定のモニターマップ上で、OS の仮想デスクトップ座標を編集し、構成を名前付きプロファイルとして保存・適用する。ウィンドウ HWND のスナップショット（PLAN_REJECT）とは別物。

## 機能概要

1. 選択モニタに `monitor_area.left/top` と解像度を表示。left/top を number input で変更し「OS に適用」。
2. マップ上ドラッグで相対位置を変え、離したときに適用（ライブ中はプレビューのみ）。
3. プロファイル: 各出力の安定 ID + 座標 + 解像度 + プライマリフラグ。
4. 安定 ID は **先に EDID シリアルを SetupAPI から取る作業** が前提。取れない個体はアダプタ名 + 解像度の弱いキーで、適用時は確認ダイアログ。

## ユースケース

- UC-1 ノート持ち歩きで、ドック接続時に「自宅3枚」プロファイルを適用。
- UC-2 マップで上下が逆のモニタをドラッグして直す。
- UC-3 一部モニタが無い状態でプロファイル適用 → 欠けた出力をスキップし警告。

## 画面遷移

```
モニター構成タブ（既存）
  選択 → 右ペインまたは下部に XY フォーム（新規）
  ドラッグ中 → プレビュー
  ドロップ → 確認ダイアログ「OS の配置を変更します」
  プロファイル保存 → 名前入力
  プロファイル適用 → 確認 → CCD
```

初心者: マップはこれまでどおりグループ/順位/プライマリ。XY 編集は「詳細」を開くまで隠す（学習コスト）。

上級者: キーボードで left/top を直接。

## 処理フロー

適用:

```
validate no complete overlap of all displays
build DEVMODE for each path
ChangeDisplaySettingsExW(... CDS_UPDATEREGISTRY | CDS_NORESET) per adapter
ChangeDisplaySettingsExW(NULL, NULL, ..., CDS_NONE)  // apply
if fail: revert from snapshot taken at start
emit display-changed
```

保存: config.json の `display_profiles: Vec<DisplayProfile>`。

## データ構造

```rust
pub struct DisplayOutputId {
    pub edid_serial: Option<String>,
    pub device_id: String,      // 今の serial_number 相当
    pub adapter_name: String,   // \\.\DISPLAY1 は不安定なので参考情報
}

pub struct DisplayLayoutEntry {
    pub id: DisplayOutputId,
    pub left: i32,
    pub top: i32,
    pub width: i32,
    pub height: i32,
    pub is_primary: bool,
}

pub struct DisplayProfile {
    pub name: String,
    pub entries: Vec<DisplayLayoutEntry>,
}
```

`AppConfig` に `display_profiles`。serde default 空配列。

## エラーハンドリング

適用失敗で必ずスナップショットへ戻す。戻せない場合は「Windows のディスプレイ設定を開く」リンク（`ms-settings:display`）。`open_url` の allowlist に `ms-settings:` は入れず、専用コマンド `open_display_settings` にする。

確認ダイアログなしの自動適用はしない。

## テスト方針

自動: プロファイルのマッチング（EDID 優先、欠落時スキップ）を純粋関数で。

```rust
pub fn match_profile<'a>(
    profile: &'a DisplayProfile,
    present: &[DisplayOutputId],
) -> MatchResult
```

Win32 の CCD 呼び出しは手動専用。仮想マシンでも失敗しうるので E2E 必須にしない。

セキュリティ: フロントから任意の DEVMODE バイナリを受け取らない。left/top/width/height の数値のみ。width/height の変更（解像度変更）は 0.4 では入れず、位置だけにする（リスク低減）。SPECv0.3 も座標中心。解像度変更は明示的に SCOPE 外。

パフォーマンス: 適用は 1〜3 秒かかってよい。UI はスピナー。

## AI 実装手順（承認後のみ。D01〜D06 完了後）

この機能は小型モデル単独に向いていない。実装するなら:

1. EDID 読み取りだけを別 PR にする（配置はまだ変えない）。
2. 読み取り結果をマップのデバッグ表示に出す。
3. 位置適用はさらに別 PR。リバート必須。

### 対象ファイル（段階1 EDID）

作成: `src-tauri/src/edid.rs`  
変更: `monitor.rs` の `enhance_monitor_details`

SetupAPI の `SetupDiGetClassDevsW` + `GUID_DEVINTERFACE_MONITOR` + registry `EDID` バイナリ。シリアルは EDID の descriptor から ASCII。失敗したら今の DeviceID フォールバック。

テスト: サンプル EDID バイト列（フィクスチャファイル `src-tauri/tests/fixtures/edid_sample.bin`）をパースする純粋関数。

```rust
pub fn parse_edid_serial(edid: &[u8]) -> Option<String>;
```

入力: 128バイト EDID。  
出力: `Some("ABC123")` または None。

Win32 列挙はテストしない。
