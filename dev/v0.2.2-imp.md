### 検証結果

| 対象 | 結果 |
| --- | --- |
| `git diff --check` | 成功。空白エラーなし |
| Markdown ローカルリンク | 全 Markdown を検査して成功。D06 の既存リンク切れ 1 件を修正 |
| PowerShell 構文 | `dev/scripts/` の 2 本を Parser で検査して成功 |
| Git 除外 | `dev/private/`、`dev/temp/`、`release/`、`*.pfx`、`*.p12` の除外を確認。該当する追跡済みファイルなし |
| `npm test` | 成功。1 ファイル、7 テスト |
| `npm run build` | 成功。`pwsh` の前処理、TypeScript、Vite ビルドを完走 |
| `cargo test --manifest-path src-tauri/Cargo.toml` | 成功。63 テスト |
| `npm run tauri build` | 成功。Release 実行ファイルと `ChuwitchWindow_0.2.1_x64-setup.exe` を生成 |

初回の Rust テストは旧プロジェクトパスを保持した `src-tauri/target/` の生成キャッシュにより失敗した。対象が `C:\develop\ChuwitchWindow\src-tauri\target` であることを確認して `cargo clean` を実行し、9.6 GiB の生成物を削除した後に再測定した。再測定で `dispatch_cli_action` の `Result<bool, ParseError>` を `bool` として扱う型不一致を確認し、初回起動と第二インスタンスの双方で `Ok(true)`、`Ok(false)`、`Err` を明示処理するよう修正した。

その後の Tauri ビルドではアプリ本体の Release コンパイルまで成功したが、`tauri.conf.json` の `targets: "all"` が採用していない WiX/MSI まで生成し、`light.exe` で失敗した。正規配布形式と公開スクリプトに合わせてバンドル対象を `nsis` に限定した。

`cargo fmt --check` は今回触っていない既存モジュールを含む全体の未整形により失敗した。無関係な大量差分を避けるため、D02 の対象である `lib.rs` と `action.rs` だけを `rustfmt` で整形・確認した。

### 追加対応と申し送り

- Git 除外解除後に既存スクリプト 2 本を確認し、`update-ChuwitchWindow-version.ps1` と `publish-release-ChuwitchWindow-all.ps1` へ改名した。公開スクリプトは成果物生成・公開失敗時に非 0 で終了するようにした。
- `dev/private/` と `dev/temp/` を作成した。移管が必要な非公開資料・一時制作物、追跡済みの証明書は見つからなかった。
- 外部公開、署名、マージは実施していない。公開スクリプトとバージョン更新スクリプトは副作用を避けるため構文検査のみとした。
- 既存の Rust 未コミット変更は保持し、ビルドを阻害していた D02 の型不一致だけを修正した。RDP 操作に関する `window.rs` の既存変更は今回のコミット対象から除外する。
