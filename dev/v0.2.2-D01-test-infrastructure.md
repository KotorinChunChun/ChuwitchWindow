# D01 自動テスト基盤とテストデータ生成

状態: 短期 **0.2.2**。最初に実装する（実装作業は本記録とは別に行う）。

## 背景

Rust 側は `rule` / `config` / `window` 計算 / `arrange` レイアウト / `pin` / `logic::group_windows_by_monitor` に単体テストがある。フロントはゼロ。CI はゼロ。ウィンドウ移動の正しさは実機目視に依存し、小型モデルの改修が回帰を生む。

本プロジェクトは HTTP API を持たない（GitHub Releases 確認を除く）。MSW は不要。Python / pytest は不要。SQLite も当面不要。

## 目的

人手でしか確認できない範囲を「本物の HWND を動かすこと」と「UAC / 物理ホットプラグ / グローバルホットキー」に限定する。計算・ルール・設定・CLI パース・React パネルは自動で落とす。

## 機能概要

1. Rust: 既存 `#[cfg(test)]` を維持し、フィクスチャモジュールを追加する。
2. フロント: Vitest + Testing Library + jsdom。
3. テストデータ生成: Rust / TS それぞれに builder。Faker 相当は自前の決定論 builder で足りる（個人情報を捏造する必要がない）。
4. npm scripts と cargo test を README / DEV から叩けるようにする。
5. 任意: GitHub Actions で `npm test` と `cargo test`（Windows runner）。コード署名は扱わない。

使わないもの: Jest（Vite と二重）、Playwright のブラウザ E2E（本アプリの価値は OS ウィンドウ）、Storybook（中期）、pytest、MSW。

Tauri の真の E2E は中期。0.2.2 では「ヘッドレス計算 + UI コンポーネント」まで。

## ユースケース

- UC-1 開発者が `npm test` でルール UI とホットキー表示の回帰を見る。
- UC-2 開発者が `cargo test` で配置計算と除外判定を見る。
- UC-3 AI エージェントがフィクスチャ builder で新しい異常系を足す。
- UC-4 CI が PR で赤を出す。

## 画面遷移

## エラーハンドリング

テスト失敗は非ゼロ終了。フィクスチャの不正（left > right）は `build()` で panic / throw し、曖昧なテストを作らせない。

## テスト方針

自分自身（テスト基盤）の受け入れ:

- `npm test` が 10 秒以内に終わる（ユニットのみ）。
- `cargo test` が Win32 を叩かないテストは 5 秒以内。
- 乱数非使用。時刻が必要な場合は引数で注入（今は不要）。

## AI 実装手順（小型モデル向け）

### 対象ファイル

| 操作 | パス |
| --- | --- |
| 変更 | `package.json` |
| 作成 | `vitest.config.ts` |
| 作成 | `src/test/setup.ts` |
| 作成 | `src/test/fixtures.ts` |
| 作成 | `src/lib/ruleUtils.test.ts` |
| 作成 | `src-tauri/src/test_support.rs` |
| 変更 | `src-tauri/src/lib.rs`（`mod test_support;` は `#[cfg(test)]`） |
| 変更 | `docs/DEVELOPERS_GUIDE.md` |

`lib.rs` に常時 `mod test_support` を出さない。

### 作成する関数（TypeScript）

`createWindow(partial?: Partial<WindowUIData>): WindowUIData`

- 引数: 上書きしたいフィールド。省略時は notepad 相当。
- 戻り値: 完全な `WindowUIData`。
- 入力例: `createWindow({ process_name: "mstsc.exe", is_fullscreen: true })`
- 出力例: `{ hwnd: 1, title: "Untitled", process_name: "mstsc.exe", class_name: "Notepad", is_pinned: false, is_fullscreen: true, is_minimized: false, is_maximized: false, style: 0, ex_style: 0 }`

`createConfig(partial?: Partial<AppConfig>): AppConfig` — 同様。デフォルトホットキーは `App.tsx` / 型と一致させる。

### サンプルコード

`vitest.config.ts`:

```ts
import { defineConfig } from "vitest/config";
import react from "@vitejs/plugin-react";
import path from "node:path";

export default defineConfig({
  plugins: [react()],
  test: {
    environment: "jsdom",
    setupFiles: ["src/test/setup.ts"],
    include: ["src/**/*.test.ts", "src/**/*.test.tsx"],
  },
  resolve: {
    alias: { "@": path.resolve(__dirname, "./src") },
  },
});
```

`src/lib/ruleUtils.test.ts` 冒頭:

```ts
import { describe, expect, it } from "vitest";
import { wildcardMatch, matchNode } from "./ruleUtils";
import { createWindow } from "../test/fixtures";

describe("wildcardMatch", () => {
  it("matches mstsc*.exe case-insensitively", () => {
    expect(wildcardMatch("MSTSC.EXE", "mstsc*.exe")).toBe(true);
  });
  it("rejects extra chars for ?", () => {
    expect(wildcardMatch("app12.exe", "app?.exe")).toBe(false);
  });
});
```

### Rust test_support

```rust
#![cfg(test)]
use crate::monitor::{MonitorInfo, MonitorRect};
use crate::window::WindowInfo;

pub fn rect(l: i32, t: i32, r: i32, b: i32) -> MonitorRect {
    assert!(r > l && b > t, "invalid rect");
    MonitorRect { left: l, top: t, right: r, bottom: b }
}
```

`logic.rs` の `create_mock_window` をこれに置換して重複を減らす。置換は同一 PR で rule/logic/arrange の3ファイルまで。全置換は必須としない。

### やってはいけないこと

- `#[test]` から `EnumWindows` や `SetWindowPos` を呼ばない。
- `npm test` で Tauri を起動しない。
- スナップショットテストで Tailwind の class 文字列全体を固定しない（壊れやすい）。
