# 品質基準とゲート

## コードカバレッジ目標

Rust のカバレッジ計測には、中期で `cargo llvm-cov` を導入する。0.2.2 では計測を必須とせず、代わりに新しい純粋関数にテストを必須とする。

| 領域 | 0.2.2 目標 | 1.0 目標 |
| --- | --- | --- |
| `rule.rs` | 行の既存維持 + 新規分岐 | 90% |
| `action.rs` / restore_plan / owning_monitor | 90% | 90% |
| `window.rs` unsafe 列挙 | 測定しない | 計算関数のみ 80% |
| `*.tsx` | ルールユーティリティ 80%、コンポーネントは主要パス | 設定パネル 60% |
| 全体ライン | 数値ゲートなし | 純粋モジュールだけ数値 |

カバレッジの計測を目的として、CI で EnumWindows を呼び出してはならない。

## パフォーマンス基準

| 指標 | 基準 | 測り方 |
| --- | --- | --- |
| トレイ常駐 RSS | 設定画面を閉じた状態で 30MB 未満を目標（作者実測 10MB 級を維持） | タスクマネージャ。リリースチェック |
| 設定画面オープン | 250MB 級は許容。閉じたら戻る | 開閉前後 |
| シフト実行 | 窓30で 500ms 以内が目標 | 手動ストップウォッチ |
| ホットキー遅延 | 押下から動き出し 100ms 級 | 体感 |
| `npm test` | 15s 以内 | CI / ローカル |
| `cargo test` | 30s 以内（マシン差あり） | 同上 |

超えたら機能追加より原因調査。常時 WebView を増やさない。

## セキュリティ基準

- 既定は一般権限。管理者はユーザー操作でのみ（変更しない）。
- アプリは自動でネットワークを使わない（D09）。ユーザーが押した GitHub リンクのみブラウザ起動してよい。
- `open_url` と CSP は現状維持（Q12。D06 は実施しない）。
- 設定ファイルはユーザディレクトリのみ。
- ログにウィンドウタイトルは出してよい（ローカル）。
- インポート JSON は serde の型に乗らないフィールドを無視。コード実行なし。
- コード署名は本リポジトリでは行わない。MSI X 側の工程。

## UI 品質基準

- 最小ウィンドウ 800x600。情報切れよりスクロール。
- 破壊的操作（リセット、ログ全消去、設定インポート）は確認ダイアログ。
- 色だけで状態を伝えない。Primary は文字ラベル既存どおり。
- フォーカスリングが見える（0.2.2 から `outline` を削らない）。
- 日本語 UI を英語化しない（本プロジェクトのユーザー向け文言は日本語）。
- アニメーションはダイアログ程度。常駐経路にアニメを足さない。
